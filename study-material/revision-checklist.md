# Revision Checklist

Mark each item only when you can explain it and apply it to a scenario.

## Platform and models

- [ ] I can choose between chat, Projects, research, and Artifacts based on the task.
- [ ] I can explain the Haiku, Sonnet, and Opus tradeoffs.
- [ ] I can separate durable context from task-specific context.

## Prompting

- [ ] I can write a prompt with role, task, context, audience, constraints, and format.
- [ ] I can decompose a compound request into checkable steps.
- [ ] I can identify the exact failure before revising a prompt.

## Evaluation

- [ ] I verify specific consequential claims against the source of record.
- [ ] I check for omissions, not only fabricated details.
- [ ] I know when human review is required.
- [ ] I can adapt accurate content for a defined audience without hiding uncertainty.

## Workflow design

- [ ] I can map a process before proposing automation.
- [ ] I can separate bounded drafting or extraction from accountable decisions.
- [ ] I can identify where approval and escalation belong.

## Configuration

- [ ] I know what belongs in Project instructions versus a one-off prompt.
- [ ] I can identify and remove stale or conflicting knowledge.
- [ ] I can assess connector access and ownership.

## Governance and privacy

- [ ] I minimize, redact, or pseudonymize data before upload.
- [ ] I inspect free text for indirect identifiers.
- [ ] I know that prompts and disclaimers are not external controls.
- [ ] I escalate high-impact, regulated, or uncertain decisions.

## Troubleshooting

- [ ] I collect exact inputs and configuration before diagnosing.
- [ ] I investigate what changed after a regression.
- [ ] I optimize quality, cost, latency, and maintainability together.

## Exam practice

- [ ] I can explain every missed practice question.
- [ ] I can finish a mock exam under its time limit.
- [ ] I read multiple-response instructions carefully.
- [ ] I answer every item and return to flagged questions.
